# 今日の特集（feature.json）の作り方

朝のニュースのページに毎朝入る「特集」。深く・面白く・正確に。読むのに3〜5分。

## 先に：表紙のイラストも毎朝1枚描く（2026-11-19〜）
特集を書く前に、同じフォルダの `COVER.md` を読み、その指示どおりに今日の表紙のイラストを描いて、作業フォルダに `cover.json` として保存する（10分を目安に。見本は cover_example.json）。
ページを作るとき（build_page.py）は、特集のファイルに続けて **cover.json も引数の最後に並べる**。
例：`python3 build_page.py magazine.html out/video.json data.json index.html feature_ai.json feature_film.json feature_fashion.json cover.json`
うまく描けなかった日は cover.json を作らず、引数にも入れない（既定の絵が出る）。最終メッセージに「表紙＝（motif）」を1行足す。

## 毎日3本
毎朝 `ai`・`film`・`fashion` の3本を作る。ファイルは feature_ai.json / feature_film.json / feature_fashion.json。
- 過去の題材（feature_log.json のタイトル）と同じものは選ばない。映画は毎日別の作品、ファッションは毎日別の切り口（アウター、靴、小物、雨の日、休日、きれいめ、など）。
- fashion はプロジェクトメモリの fashion-taste（翔太さんの好み）を必ず読んで合わせる。
- fashion は雑誌（メモリにある参考誌）の最新号・Web記事が今すすめている着こなしやブランドを出発点にする。好みのブランドだけで固めず、毎回1つは新しいブランドを紹介する。
- 1本あたり調べものは15分を目安に。まとまらなかったテーマはその日は載せない。

## テーマごとの狙い
- **ai**：直近1〜2週間の論文や実験から「まさかの結果」「へえ」となる1本。何をどう調べ、何が分かり、どこが意外で、どこは割り引くべきかまで書く。一次ソース（arXiv、研究機関の発表）を必ず読む。
- **film**：公開中か近日公開（日本）の話題作を1本、濃く。監督の狙い、見どころ、評価が割れている点、関連作。重大なネタバレはしない。facts に監督・出演・公開日・上映時間・配給。
- **fashion**：今の季節のおすすめコーディネートを1つ。メモリの好みに合わせ、着用アイテムを全部 items に（ブランド・品名・価格・公式URL）。SNS投稿は linkText を「投稿を見る」にしてURLで紹介する。SNSの写真は転載しない。
  - **リンクカード（2026-11-19〜）**：ページでは items と look が「写真つきのリンクカード」になる。写真はリンク先ページの **og:image（SNSで共有されたときに出る代表画像）のURLをそのまま参照**するだけで、画像をダウンロードしたりリポジトリに保存したりはしない。
  - **look（必須に近い）**：コーデの出発点にした雑誌の記事・特集ページ（UOMO / BRUTUS / POPEYE のWeb記事、ブランドのLOOKBOOKなど）を1〜2件。コーデの雰囲気が写真で伝わるページを選ぶ。Instagram・WEAR などSNSのページは look にしない（写真が出ないうえ転載に近くなる）。
  - **写真URLの取り方**：items と look のURLを1つずつ WebFetch で開き、「このページの og:image（無ければ twitter:image）と og:title、og:site_name のmetaタグの値をURLのまま正確に答えて」と頼む。返ってきた https の画像URLを img に入れる。見つからない・テキストしか返らないページは img を空にする（カードはブランド名の文字で表示される）。推測でURLを作らない。1件1分以内、全部で5分を目安に。
  - **3つの価格帯（picks、2026-11-19〜 翔太さん希望）**：その日のテーマに合うアイテム（例：雨の日ならアウター、靴の日なら靴）を1種類決め、同じ種類で「ハイブランド（例：PRADA、Margiela、Lemaire など）」「ミドル（例：DAIWA PIER39、FreshService、Graphpaper、Studio Nicholson など）」「ファスト（例：GU、UNIQLO、ZARA など）」から1点ずつ、計3点おすすめする。tier は high / mid / fast。picksTitle に「雨の日のアウター、3つの価格帯で」のような一言。note には、その価格帯を選ぶ理由（何にお金を払うか、どこで割り切るか）を40字前後で。価格と販売中であることは商品ページで確かめる（確かめられない価格は書かない。古い表示しか見つからないときは note に「価格は公式で要確認」）。img は items と同じく og:image が取れたときだけ。毎日ブランドを変える（fashion の記録に "picks": ["PRADA","DAIWA PIER39","UNIQLO"] のようにブランド名も残し、前の日と同じブランドを続けない）。
  - 商品ページが取れないブランド（UNIQLO・BEAMSなどテキストしか返らないサイト）は、同じ商品が載っている別の公式ページ（ブランド直営のオンラインストアやZOZOTOWNの商品ページなど）で og:image が取れれば、そちらを url にしてよい。

## 公式の予告編・映像（videos、2026-11-26〜 翔太さん希望）
特集の最後（本文のあと）に、公式の予告編へ飛べる「WATCH」カードが出る。YouTubeのURLなら、サムネイルはページが動画IDから自動で出すので img は要らない。
- **film は毎日必須**：その作品の日本版の予告編（本予告 > 予告編 > 特報・ティザー の順で新しいもの）を1件、あれば2件まで。日本版が無い作品は海外の公式トレーラーでよい。
- **ai・fashion は任意**：研究機関の公式デモ動画、ブランド公式のコレクション映像など、公式が出した映像があれば1件。無理に探さない。
- **探し方**（1件3分以内）：
  1. WebSearch で「作品名 予告編」を探し、映画ニュースの記事（MOVIE WALKER PRESS、シネマトゥデイ、映画.com、映画ナタリー、クランクイン!、オリコンなど）を WebFetch で開いて、「記事に埋め込まれている YouTube の動画ID（youtube.com/embed/〇〇 や youtu.be/〇〇）をそのまま答えて」と頼む。
  2. 見つかったIDを `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=ID&format=json` で WebFetch し、title と author_name（チャンネル名）を確かめる。作品名が title に入っていなければ使わない。
  3. チャンネルは 配給会社・製作会社・スタジオの公式（例：映画会社ビターズ・エンド、ワーナー ブラザース ジャパン、Netflix Japan、A24）を最優先。見つからなければ、映画メディアや映画館の公式チャンネル（MOVIE WALKER PRESS、シネマトゥデイ、映画.com、イオンシネマなど）が載せた予告編でよい。個人の転載・切り抜き・ファンメイドは使わない。
  4. 推測で動画IDやURLを作らない。確かめられなかった日は videos を省く（カードは出ないだけ）。
- **映画ニュースにも付ける**：特集を書き終えたら、data.json の映画セクション（id が film）の各項目で、特定の作品を扱っているものに同じ手順で予告編を探し、その項目に `"videos": [...]`（1件）を足して data.json を保存し直してから build_page.py を動かす。1項目3分、全部で10分まで。見つからない項目はそのまま。ほかのジャンルの項目には付けない。
- 形式：`"videos": [{"url": "https://www.youtube.com/watch?v=ID", "kind": "本予告", "title": "映画『〇〇』本予告", "channel": "oEmbed の author_name そのまま"}]`
  - kind はカード左上の小さなラベル（本予告／予告編／特報／ティザー／公式映像 など、10字以内）。title は動画の中身が分かる短い名前（oEmbed の title から公開日などの宣伝文を除いたもの、40字以内）。

## ルール
- Web検索と記事の読み込みで事実を確かめる。確認できない数字・発言・価格は書かない。推測は推測と書く。
- 引用は短く、訳したら「（訳）」と付ける。
- 文体は下の「文体」の節に従う。専門用語は初出で一言説明。
- 出典 src は実際に読んだページだけ。

## 文体
翔太さんの希望：村上春樹のエッセイ（『村上朝日堂』『村上ラヂオ』『走ることについて語るときに僕の語ること』など）のように、すっと読める文章にする。真似るのは読みやすさの作り方で、文章そのものや決まり文句（「やれやれ」など）を借りるのではない。見本は tools/feature_example.json。
- 一文を短く。1つの文には1つのことだけ。長い文が続いたら、短い文を1つ挟んでリズムを作る。
- ふだんの言葉で書く。硬い漢語や業界用語は言い換える（「〜を実施した」→「〜をやってみた」、「示唆する」→「〜らしい」）。体言止めや「〜的」「〜性」の連発は避ける。
- 読者に話しかけるように、順を追って書く。「では、どうすればいいのか。」「なぜだろう。」のような短い問いで次へつなぐ。
- 抽象的な話には、身近なものの例えを1つ添える（例えだと分かる書き方で。1ブロックに1つまで）。
- 力まない。大げさな形容やあおりは使わず、淡々と、少しだけユーモアを。意見は「〜と思う」「たぶん〜だ」と控えめに書き、事実と混ぜない。
- だ・である を基本に、「〜けれど」「〜のだ」などのやわらかい言い回しを混ぜる。
- 守ること：書き手はAIなので、自分の体験談や思い出を作らない（「僕」の昔話は書かない）。読みやすさのために事実・数字・引用を変えたり足したりしない。
- リードは場面や問いから入る。points（要点）も短い文で。

## 形式（feature.json）
```json
{
  "topic": "ai | film | fashion",
  "label": "AI | 映画 | ファッション",
  "kicker": "一言のあおり（30字以内）",
  "title": "見出し（40字以内、数字や意外性を入れる）",
  "lead": "リード文（120〜180字）",
  "facts": [{"k": "論文", "v": "…"}],
  "pointsLabel": "ここが面白い",
  "points": ["要点を3つ。各60字前後"],
  "blocks": [{"h": "小見出し", "body": "240〜380字。2〜3段落に分ける（区切りは \n）"}],
  "quote": {"text": "印象的な一言（60字以内）", "who": "誰の言葉か"},
  "items": [{"brand": "", "name": "", "price": "", "note": "", "url": "https://…", "linkText": "公式ページを見る", "img": "https://…"}],
  "picksTitle": "雨の日のアウター、3つの価格帯で",
  "picks": [{"tier": "high | mid | fast", "brand": "", "name": "", "price": "", "note": "", "url": "https://…", "img": "https://…（og:image）"}],
  "videos": [{"url": "https://www.youtube.com/watch?v=…", "kind": "本予告", "title": "映画『…』本予告", "channel": "公式チャンネル名"}],
  "look": [{"url": "https://…（雑誌の記事）", "img": "https://…（og:image）", "site": "UOMO", "title": "og:title（サイト名の部分は除く）", "note": "この記事をどう使ったか一言（40字以内）"}],
  "terms": [{"w": "本文に出てくる言葉", "d": "40〜90字の解説"}],
  "src": [["サイト名", "https://…"]]
}
```
- terms（用語タップ解説）：読者がつまずきそうな固有名詞・専門用語を3〜6個。ページ上でその言葉をタップすると解説が出る。w は lead・points・blocks の本文に出てくる表記そのまま（2文字以上）。d は「それは何か」を1〜2文で、確かめた事実だけを書く。本文中ですでに説明した言葉や、誰でも知っている言葉は入れない。
- facts は3〜5行、blocks は4〜5個。最後の block は「割り引いて読む点」や「こんな人におすすめ」などの締め。
- videos は film のとき必須（確かめられなかった日だけ省略）、ほかは省略可。
- items は fashion のとき必須、ほかは省略可。picks は fashion のとき3件（high・mid・fast を1件ずつ）。look は fashion のとき1〜2件（配列。1件ならオブジェクトでも可）。items の img・look の img は og:image が確かめられたときだけ。quote は無ければ省略。

## 記録
作ったら1本ごとに `feature_log.json` の配列の末尾に `{"date": "YYYY-MM-DD", "topic": "…", "title": "…"}` を追加する。 fashion は "picks"（3つの価格帯のブランド名）も入れる。
