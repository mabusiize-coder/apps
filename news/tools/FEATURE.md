# 今日の特集（feature.json）の作り方

朝のニュースのページに毎朝入る「特集」。深く・面白く・正確に。読むのに3〜5分。

## 先に：表紙のイラストも毎朝1枚描く（2026-11-19〜）
特集を書く前に、同じフォルダの `COVER.md` を読み、その指示どおりに今日の表紙のイラストを描いて、作業フォルダに `cover.json` として保存する（10分を目安に。見本は cover_example.json）。
ページを作るとき（build_page.py）は、特集のファイルに続けて **cover.json も引数の最後に並べる**。
例：`python3 build_page.py magazine.html out/video.json data.json index.html feature_ai.json feature_film.json feature_fashion.json cover.json`
うまく描けなかった日は cover.json を作らず、引数にも入れない（既定の絵が出る）。最終メッセージに「表紙＝（motif）」を1行足す。

## 毎日3本
毎朝 `ai`・`film`・`fashion` の3本を作る。ファイルは feature_ai.json / feature_film.json / feature_fashion.json。
- 過去の題材（feature_log.json のタイトル）と同じものは選ばない。映画は毎日別の作品、ファッションは毎日別の切り口（アウター、靴、小物、雨の日、休日、きれいめ、など）。
- fashion はプロジェクトメモリの fashion-taste（翔太さんの好み）を必ず読んで合わせる。
- fashion は雑誌（メモリにある参考誌）の最新号・Web記事が今すすめている着こなしやブランドを出発点にする。好みのブランドだけで固めず、毎回1つは新しいブランドを紹介する。
- 1本あたり調べものは15分を目安に。まとまらなかったテーマはその日は載せない。

## テーマごとの狙い
- **ai**：直近1〜2週間の論文や実験から「まさかの結果」「へえ」となる1本。何をどう調べ、何が分かり、どこが意外で、どこは割り引くべきかまで書く。一次ソース（arXiv、研究機関の発表）を必ず読む。
- **film**：公開中か近日公開（日本）の話題作を1本、濃く。監督の狙い、見どころ、評価が割れている点、関連作。重大なネタバレはしない。facts に監督・出演・公開日・上映時間・配給。
- **fashion**：今の季節のおすすめコーディネートを1つ。メモリの好みに合わせ、着用アイテムを全部 items に（ブランド・品名・価格・公式URL）。SNS投稿は linkText を「投稿を見る」にしてURLで紹介する。SNSの写真は転載しない。img はブランド公式サイトの商品画像の https URL が確認できたときだけ入れる。

## ルール
- Web検索と記事の読み込みで事実を確かめる。確認できない数字・発言・価格は書かない。推測は推測と書く。
- 引用は短く、訳したら「（訳）」と付ける。
- 文体は下の「文体」の節に従う。専門用語は初出で一言説明。
- 出典 src は実際に読んだページだけ。

## 文体
翔太さんの希望：村上春樹のエッセイ（『村上朝日堂』『村上ラヂオ』『走ることについて語るときに僕の語ること』など）のように、すっと読める文章にする。真似るのは読みやすさの作り方で、文章そのものや決まり文句（「やれやれ」など）を借りるのではない。見本は tools/feature_example.json。
- 一文を短く。1つの文には1つのことだけ。長い文が続いたら、短い文を1つ挟んでリズムを作る。
- ふだんの言葉で書く。硬い漢語や業界用語は言い換える（「〜を実施した」→「〜をやってみた」、「示唆する」→「〜らしい」）。体言止めや「〜的」「〜性」の連発は避ける。
- 読者に話しかけるように、順を追って書く。「では、どうすればいいのか。」「なぜだろう。」のような短い問いで次へつなぐ。
- 抽象的な話には、身近なものの例えを1つ添える（例えだと分かる書き方で。1ブロックに1つまで）。
- 力まない。大げさな形容やあおりは使わず、淡々と、少しだけユーモアを。意見は「〜と思う」「たぶん〜だ」と控えめに書き、事実と混ぜない。
- だ・である を基本に、「〜けれど」「〜のだ」などのやわらかい言い回しを混ぜる。
- 守ること：書き手はAIなので、自分の体験談や思い出を作らない（「僕」の昔話は書かない）。読みやすさのために事実・数字・引用を変えたり足したりしない。
- リードは場面や問いから入る。points（要点）も短い文で。

## 形式（feature.json）
```json
{
  "topic": "ai | film | fashion",
  "label": "AI | 映画 | ファッション",
  "kicker": "一言のあおり（30字以内）",
  "title": "見出し（40字以内、数字や意外性を入れる）",
  "lead": "リード文（120〜180字）",
  "facts": [{"k": "論文", "v": "…"}],
  "pointsLabel": "ここが面白い",
  "points": ["要点を3つ。各60字前後"],
  "blocks": [{"h": "小見出し", "body": "240〜380字。2〜3段落に分ける（区切りは \n）"}],
  "quote": {"text": "印象的な一言（60字以内）", "who": "誰の言葉か"},
  "items": [{"brand": "", "name": "", "price": "", "note": "", "url": "https://…", "linkText": "公式ページを見る", "img": "https://…"}],
  "terms": [{"w": "本文に出てくる言葉", "d": "40〜90字の解説"}],
  "src": [["サイト名", "https://…"]]
}
```
- terms（用語タップ解説）：読者がつまずきそうな固有名詞・専門用語を3〜6個。ページ上でその言葉をタップすると解説が出る。w は lead・points・blocks の本文に出てくる表記そのまま（2文字以上）。d は「それは何か」を1〜2文で、確かめた事実だけを書く。本文中ですでに説明した言葉や、誰でも知っている言葉は入れない。
- facts は3〜5行、blocks は4〜5個。最後の block は「割り引いて読む点」や「こんな人におすすめ」などの締め。
- items は fashion のとき必須、ほかは省略可。quote は無ければ省略。

## 記録
作ったら1本ごとに `feature_log.json` の配列の末尾に `{"date": "YYYY-MM-DD", "topic": "…", "title": "…"}` を追加する。
