# 毎日の講義（learn/）の作り方

翔太さん（映像編集者。なみきゴルフのYouTube編集など）の希望（2026-11-28）：
「デザイン（Web・グラフィック）と映像（編集・撮影）を、基礎から実践まで最短で。素人や平凡なクリエイターと差がつく本当に重要な教えを、一冊の素晴らしい本を読んだような学びとして。毎日続けて、効率よく体系的に。スマホを閉じても聞ける形で。図解もあるとわかりやすい」

書き手は「トップの売れっ子デザイナーであり、トップの映像クリエイター」の視点で書く。ただし AI なので、自分の体験談や思い出は作らない。

## 毎日の手順
1. `learn/lessons/index.json` の最後の no に 1 を足したものが今日の回（ファイルが無ければ 1）。`learn/curriculum.json` の lessons からその no の講（book・n・part・title・goal・keys）を取る。no が curriculum に無ければ全講おわり。何も作らず終える。
2. 同じ本の直前2講（`learn/lessons/NNN.json`）を読み、話が重ならないように、前の内容を踏まえて書く。
3. その講のテーマを Web 検索で調べ、定番の考え方や数値（例：シャッタースピードの目安、ラウドネスの基準、配色比率）を確かめる（20分まで）。
4. 下の形式で講義の JSON を書き、作業フォルダに保存する（リポジトリの外。例：/tmp/lesson.json）。
5. 図を確かめる（下の「図解」）。
6. `python3 learn/tools/make_lesson.py /tmp/lesson.json` を動かす（約15〜25分。Gemini の声を作る）。`learn/lessons/NNN.json`・`NNN.mp3`・`index.json` ができる。
7. `learn/` だけを main にコミットして push（メッセージ「講義 第N回」）。push が弾かれたら `git pull --rebase` してからもう一度。

## 内容の方針
- curriculum の goal と keys を必ず扱う。keys は骨組みで、そのまま見出しにしなくてよい。
- 「なんとなく知っている」で終わらせない。プロが実際に使う判断基準・数値・手順を出す（例：「迷ったら余白を1.5倍」「1/(2×fps) のシャッター」）。根拠が確かめられない数値は書かない。
- 素人との差になる点を毎回はっきり言う（「素人は〜する。プロは〜する」の対比は1講に1〜2回まで）。
- 翔太さんの仕事につなげる：映像の本はYouTube（なみきゴルフのようなゴルフのバラエティ・企画動画）、デザインの本はサムネイル・テロップ・Webの例を多めに。毎回は不要、自然に入るときだけ。
- 2冊はつながっている。テロップやサムネイルの講では、もう一方の本の講（例：「デザインの本の第10講で話したジャンプ率」）に触れてよい。まだ出ていない講は先取りしない。
- 実在の本・人物・作品だけを挙げる。books はその講のテーマで定評のある本を1〜2冊（著者名・書名を検索で確かめる）。前の講と同じ本は続けて出さない。

## 文体（朝のニュースの特集と同じ。村上春樹のエッセイのような読みやすさ）
- 一文を短く、1文1つのこと。ふだんの言葉。硬い漢語は言い換える。
- 読者に話しかけるように順を追う。「では、どうすればいいのか。」のような短い問いで次へ。
- 抽象的な話には身近な例えを1つ（1節に1つまで）。
- 力まず、淡々と、少しユーモア。意見は「〜と思う」と控えめに。
- 耳で聞いて分かる文にする（音声がメイン）。カッコ書き・記号・英略語の羅列を避け、数字は読みやすく。「図のように」とだけ書かず、図が見えなくても分かるように言葉で説明する。
- 見本は `learn/lessons/001.json`（第1回）。

## 長さ
- lead・sections の body・keys・practice の合計で 2,600〜3,600字（音声で約8〜11分）。
- sections は 4〜6 個。1つの body は 350〜650字、2〜4段落（区切りは \n）。

## おさらい（review）
第3回以降は必ず入れる。同じ本の前回の講から1問、もっと前の講（5〜10講前）から1問、計2問。問いは「〜なのはなぜか」「〜の目安は」など、思い出す力を使うもの。答えは2文以内。前の講の keys と本文から作る。

## 図解（fig）
- 各 section に1つ、なるべく付ける（全部で3〜6個）。言葉より図のほうが早く分かるものを選ぶ：比較（悪い例／良い例）、比率・数値、構造、流れ、構図やカメラの位置の見取り図、タイムライン。
- `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 600 340" font-family="Noto Sans JP,sans-serif">…</svg>` の形で書く。最初に `<rect width="600" height="340" fill="#F4EFE6"/>`。
- 平らな色面と線だけ。グラデーション・影・フィルターは使わない。線は #141414 で太さ2〜4。
- 色：黒 #141414、白 #FFFFFF、生成り #F4EFE6、グレー #C9C2B6、中間グレー #555、赤 #E8452C（デザインの本の色）、青 #1F4FD8（映像の本の色）、黄 #F4C744。その本の色を主役に使う。
- 使える要素：rect circle ellipse line polyline polygon path g text tspan。`<script>` `<image>` `<a>` `<foreignObject>` `<style>` `href` `url(` `on…=` は書かない（書くと図が外される）。
- 文字は14px以上、ラベルは短く（1つ12字以内）。端から20px以内に大事なものを置かない。全体で12,000字以内。
- cap は図の言いたいことを1文（40字前後）。
- 確かめ方：講義の JSON から図だけを並べた HTML を作り、Playwright でスクリーンショットを撮って目で見る。文字のはみ出し・重なり・切れがあれば直す。

## 形式
```json
{
  "no": 3, "book": "design", "n": 2, "part": "第1部 デザインの考え方", "date": "YYYY-MM-DD",
  "title": "curriculum の title のまま",
  "kicker": "一言のあおり（25字以内）",
  "lead": "導入（150〜250字）",
  "review": [{"q": "問い", "a": "答え"}],
  "sections": [{"h": "小見出し（20字前後）", "body": "本文（\nで段落）", "fig": {"svg": "<svg …>…</svg>", "cap": "図の説明"}}],
  "keys": ["今日の要点を3つ。各40字前後"],
  "practice": {"title": "課題の名前（20字以内）", "body": "10〜15分でできる具体的な課題（120〜220字）。何を、どうやって、何を確かめるか"},
  "books": [{"title": "書名（『』なし）", "who": "著者", "why": "この講との関係（50字前後）"}],
  "terms": [{"w": "本文に出る言葉", "d": "40〜90字の解説"}]
}
```
- terms は2〜5個。w は lead か body に出てくる表記そのまま。誰でも知っている言葉は入れない。
- 課題は、翔太さんが実際に手を動かせるもの（自分の動画・サムネ・スマホのカメラ・Premiere・Figma などで）。
